**2. What is implemented**
- **Rendering:**
  - `DG_DrawFrame` converts the engine's B,G,R,0 pixels into opaque RGBA.
  - It draws them to the 640×400 `<canvas id="canvas">` with `putImageData`, scaled with `image-rendering: pixelated`.
- **Input:**
  - Browser key codes are mapped to Doom key codes in `web/index.html`, covering arrows, WASD, Ctrl, Space, Shift, number keys, Tab, Enter/Esc, P and F-keys.
  - They go through a 256-entry ring buffer via `dg_key`, and `DG_GetKey` drains it.
  - Held keys are tracked so they release on blur or tab hide.
  - Menu and Pause buttons send the matching keys.
  - Mouse input is not implemented.
- **Timing:**
  - `DG_GetTicksMs` uses `emscripten_get_now`.
  - `DG_SleepMs` uses `emscripten_sleep` (Asyncify), so wipe and tic waits yield to the browser.
  - `main()` calls `doomgeneric_Tick()` in a loop and yields each frame.
- **WAD:**
  - `assets/doom1.wad` is preloaded into the module's virtual filesystem as `/doom1.wad`.
  - The game starts with `-iwad /doom1.wad`.
- **Integration:**
  - `build.sh` compiles the engine plus the platform files with emcc.
  - It writes `dist/doom.js`, `doom.wasm`, `doom.data`, `index.html` and `audio.js`.
  - `index.html` loads `doom.js`.
  - The page also has read-only state exports (`dg_in_level`, `dg_player_x` and similar) for the browser tests.
